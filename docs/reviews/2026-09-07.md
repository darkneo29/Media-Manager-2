# Application review — September 7, 2026

The review covered launch/navigation, library and discovery loading, add/edit flows, Downloads, calendar, server status, settings/backup, image caching, and Watch/widget synchronization. It combined source inspection, regression tests, simulator navigation, and cross-platform builds. It is not a claim that every server-backed interaction has been exercised against a live installation.

## Changes

- **First launch and server removal:** library loaders skip unconfigured services, clear stale data/errors, and cancel publication of superseded requests. This fixes the unsupported-URL error shown on Home in a fresh installation. Server changes clear old library state; Sonarr changes also refresh quality profiles.

- **Movie and TV root-folder editing:** single-item updates now change the destination `path` as well as `rootFolderPath`. Opening Edit no longer substitutes the first available root folder when metadata is absent. The current path supplies a fallback, unknown destinations remain unchanged, and Save waits for options to load. Folder updates are sent only when the user changes the selection. Unix and Windows server paths are covered by regression tests.
- **Poster loading:** image paths already containing a reverse proxy prefix no longer duplicate it. Relative paths without a leading slash also resolve correctly. Image authentication uses a shared origin/path check, recognizes equivalent default ports, and excludes unrelated hosts and sibling application paths.
- **Download parsing:** non-finite, negative, or overflowing byte metrics no longer trap during floating-point conversion. Queue progress rejects non-finite values, and oversized numeric history fields use decoding fallbacks. Unraid's formatted byte parser uses the same safe conversion.
- **Watch synchronization:** an older asynchronous snapshot cannot supersede a newer one on the phone. The Watch rejects older delivered snapshots, and the phone skips snapshot network work when no paired, installed Watch app can receive it.
- **Navigation coverage:** replaced the empty launch-only UI example with assertions for movie/TV empty states, Discover, Downloads/Calendar/Unraid/Settings through More, and the Radarr settings credential field.

The path change follows the servers' single-item update handlers, which use the submitted `Path` for the move destination: [Radarr MovieController](https://github.com/Radarr/Radarr/blob/develop/src/Radarr.Api.V3/Movies/MovieController.cs) and [Sonarr SeriesController](https://github.com/Sonarr/Sonarr/blob/develop/src/Sonarr.Api.V3/Series/SeriesController.cs).

## Validation

- 28 unit tests passed on the iPhone 17 Pro simulator, including seven new regression tests. Keychain and encrypted-backup tests ran with simulator signing enabled.
- iPhone navigation test passed, including the corrected Home state, unconfigured library/discovery screens, More destinations, and Radarr settings.
- iPad sidebar navigation test passed for Home, Downloads, Calendar, and Settings. Captured iPad Downloads and iPhone Calendar/Settings screenshots were visually inspected.
- Final iOS simulator build included the widget and Watch app targets.
- Final tvOS simulator Debug build passed.
- Source plist/entitlement lint and `git diff --check` passed.

Live server-side moves, active download control, paired Watch delivery, and iCloud synchronization across physical devices were not exercised. Changes are local; no release was uploaded or pushed.
